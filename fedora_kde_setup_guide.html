Fedora 44 KDE 6.7 — Complete Post-Install Guide

Hardware: AMD Ryzen 7 7800X3D + AMD Radeon RX 9070 XT (RDNA 4)

System: Fedora 44 KDE Plasma 6.7

Step 0 — DNF configuration

Makes everything faster. Do this first.

sudo nano /etc/dnf/dnf.conf

Add under [main]:

max_parallel_downloads=10
defaultyes=True
keepcache=True

Step 1 — System update + RPM Fusion

sudo dnf upgrade --refresh -y

sudo dnf install \
  https://mirrors.rpmfusion.org/free/fedora/rpmfusion-free-release-$(rpm -E %fedora).noarch.rpm \
  https://mirrors.rpmfusion.org/nonfree/fedora/rpmfusion-nonfree-release-$(rpm -E %fedora).noarch.rpm \
  -y

[!WARNING]
Fedora 44 RPM Fusion bug: the release package may enable Rawhide repo by mistake. Check:
``bash
sudo dnf repolist --all | grep -i fusion
`
If you see rpmfusion-free-rawhide enabled, fix it:
`bash
sudo dnf config-manager setopt rpmfusion-free.enabled=1
sudo dnf config-manager setopt rpmfusion-free-updates.enabled=1
sudo dnf config-manager setopt rpmfusion-free-rawhide.enabled=0
``

sudo dnf upgrade --refresh -y

Step 2 — Btrfs snapshots (safety net)

If anything goes wrong — reboot, pick a snapshot from GRUB, done.

sudo dnf install snapper grub-btrfs btrfs-assistant libdnf5-plugin-actions -y

sudo snapper -c root create-config /
sudo snapper -c root set-config ALLOW_USERS=$USER SYNC_ACL=yes
sudo restorecon -RFv /.snapshots
sudo systemctl enable --now grub-btrfsd

From now on, every dnf upgrade automatically creates a snapshot before and after.

Step 8 — Docker CE (alongside Podman)

Fedora ships Podman by default (uses Podman for Distrobox and MongoDB). Docker CE is installed separately for university coursework and full Docker Compose compatibility. Both coexist without conflict.

# Remove conflicting packages (if any)
sudo dnf remove -y moby-engine runc podman-docker

# Add Docker's official Fedora repository
sudo dnf config-manager addrepo --from-repofile=https://download.docker.com/linux/fedora/docker-ce.repo

# Install Docker CE
sudo dnf install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# Enable the Docker daemon and add your user
sudo systemctl enable --now docker
sudo usermod -aG docker $USER

[!NOTE]
You now have both container runtimes:
- docker — for university assignments, Docker Compose labs, team projects
- podman — for personal containers (MongoDB, etc.), Distrobox, rootless security

Log out and back in for the docker group to take effect.

[!WARNING]
Docker's daemon runs as root and bypasses firewalld by injecting raw iptables rules. Any port you expose with docker run -p is open to your network, even if firewalld says otherwise. Podman does not have this problem. Be mindful of what you expose.

Step 16 — KVM/QEMU Virtualization

Near-native VM performance using your CPU's AMD-V hardware virtualization. Much faster than VirtualBox for Linux guests.

# Install the full virtualization stack
sudo dnf install @virtualization edk2-ovmf swtpm swtpm-tools -y

# Add your user to the libvirt group (manage VMs without root)
sudo usermod -aG libvirt $USER

# Enable the QEMU socket (modular daemon, starts on demand)
sudo systemctl enable --now virtqemud.socket

# Start and auto-enable the default NAT network
sudo virsh net-autostart default
sudo virsh net-start default

After logging out and back in, launch virt-manager from the KDE app launcher.

[!TIP]
For Windows 11 guests: edk2-ovmf provides UEFI firmware and swtpm provides TPM 2.0 emulation — both required by Windows 11. Virt-manager configures these automatically when you select "Windows 11" during VM creation.

Step 17 — VirtualBox (for university)

Installed alongside KVM for coursework compatibility. Use VirtualBox when your course requires it (.ova files, lab instructions), KVM for everything else.

sudo dnf install akmod-VirtualBox VirtualBox kernel-devel -y
sudo systemctl restart systemd-modules-load
sudo usermod -aG vboxusers $USER

[!WARNING]
VirtualBox and KVM both use hardware virtualization (AMD-V). They coexist on disk, but you generally cannot run VMs from both at the same time. Close VirtualBox VMs before starting KVM VMs, and vice versa.

Step 18 — Tailscale (Mesh VPN)

Zero-config mesh VPN that connects all your devices into a private network. Works through NAT/firewalls without port forwarding.

# Add official Tailscale repository
sudo dnf config-manager addrepo --from-repofile=https://pkgs.tailscale.com/stable/fedora/tailscale.repo

# Install and start
sudo dnf install tailscale -y
sudo systemctl enable --now tailscaled

# Authenticate (opens browser)
sudo tailscale up --operator=$USER

Firewalld zone setup (keeps Tailscale traffic separate from your main network rules):

sudo firewall-cmd --permanent --new-zone=tailscale
sudo firewall-cmd --permanent --zone=tailscale --add-interface=tailscale0
sudo firewall-cmd --permanent --zone=tailscale --set-target=ACCEPT
# Allow direct peer-to-peer WireGuard tunnels (reduces latency)
sudo firewall-cmd --permanent --add-port=41641/udp
sudo firewall-cmd --reload

[!TIP]
The --operator=$USER flag lets you run tailscale status and other management commands without sudo.

Step 19 — Sunshine (Game Streaming)

Streams your desktop and games to any device running the Moonlight client. Pairs perfectly with Tailscale for remote streaming.

# Add official LizardByte repository (stable channel)
curl -1sLf 'https://dl.cloudsmith.io/public/lizardbyte/stable/cfg/setup/bash.rpm.sh' | sudo -E bash

# Install Sunshine (package name is case-sensitive)
sudo dnf install Sunshine -y

# Grant screen capture capability
sudo setcap cap_sys_admin+p $(readlink -f $(which sunshine))

Input emulation setup (virtual gamepad/mouse via uinput):

echo 'KERNEL=="uinput", SUBSYSTEM=="misc", OPTIONS+="static_node=uinput", TAG+="uaccess"' | sudo tee /etc/udev/rules.d/60-sunshine.rules
sudo udevadm control --reload-rules && sudo udevadm trigger
sudo modprobe uinput
echo "uinput" | sudo tee /etc/modules-load.d/uinput.conf
sudo usermod -a -G input $USER

Firewall rules:

sudo firewall-cmd --permanent --add-port={47984,47989,48010}/tcp
sudo firewall-cmd --permanent --add-port={5353,47998,47999,48000,48002,48010}/udp
sudo firewall-cmd --reload

Enable Avahi (mDNS auto-discovery for Moonlight):

sudo dnf install avahi -y
sudo systemctl enable --now avahi-daemon

Start Sunshine as a user service:

systemctl --user enable --now sunshine

Access the web UI at https://localhost:47990 to configure pairing and settings.

[!TIP]
Sunshine + Tailscale = stream from anywhere. Connect your phone/tablet/laptop to your Tailscale network, and Moonlight can find your Sunshine host — even from a coffee shop or hotel.

[!NOTE]
Headless streaming (monitor off): Wayland stops rendering when no display is attached. Either use a cheap HDMI dummy plug (~\$5), or install krfb (sudo dnf install krfb) and configure a virtual display in Sunshine's prep-commands.

⟳ REBOOT

Everything above needs a reboot to apply: kernel parameters, Mesa drivers, DKMS modules (OpenRazer, VirtualBox), kernel modules (uinput, i2c), and user group memberships (docker, libvirt, vboxusers, input, i2c, plugdev).

sudo reboot

Step 22 — MongoDB (Podman container)

MongoDB Inc. dropped Fedora support in 2019. The cleanest way to run it is in a rootless Podman container with Quadlet — it auto-starts as a systemd user service.

# Create persistent data directory
mkdir -p ~/mongodb-data

Create the Quadlet file at ~/.config/containers/systemd/mongodb.container:

[Unit]
Description=MongoDB Database Container
After=network-online.target

[Container]
Image=docker.io/library/mongo:latest
ContainerName=mongodb
PublishPort=127.0.0.1:27017:27017
Volume=%h/mongodb-data:/data/db:Z
Environment=MONGO_INITDB_ROOT_USERNAME=admin MONGO_INITDB_ROOT_PASSWORD=SuperSecretPassword

[Service]
Restart=always

[Install]
WantedBy=default.target

# Activate the service
systemctl --user daemon-reload
systemctl --user enable --now mongodb

[!NOTE]
Change SuperSecretPassword to something real. The :Z SELinux label is required on Fedora or the container can't access the volume.

Connect with the CLI: podman exec -it mongodb mongosh -u admin -p

Step 26 — DaVinci Resolve 21.0 (in Distrobox)

[!NOTE]
Important setup details from the davincibox guide:
- lshw dependency: lshw is required by the setup script to detect whether you are using an Nvidia, AMD, or Intel GPU. Some Fedora spins do not include this by default.

Step 27 — DaVinci Resolve AAC Audio Fixes

DaVinci Resolve on Linux lacks AAC audio support. We will use two different tools to fix importing (hearing audio in the timeline) and exporting (rendering to AAC).

1. Fix Importing (davinci-resolve-audio-fix):

This watches a folder and converts AAC to PCM automatically. Run this on your host Fedora system.

# Create a dedicated editing folder
mkdir ~/Montage

# Install the watcher script
git clone https://github.com/owlivion-tech/davinci-resolve-audio-fix.git ~/davinci-resolve-audio-fix
cd ~/davinci-resolve-audio-fix
bash install.sh

[!TIP]
During installation, when asked for the directory to watch, specify /home/$USER/Montage. From now on, drop your camera files into ~/Montage and they will be automatically converted for Resolve!

2. Fix Exporting (davinci-linux-aac-codec):

Adds an AAC encoder to the Deliver page in DaVinci Resolve Studio. Because it's a plugin, it must be installed inside the Distrobox container.

# Enter the container
distrobox enter davincibox

# Download the latest pre-built release
wget https://github.com/Toxblh/davinci-linux-aac-codec/releases/latest/download/aac_encoder_plugin-linux-bundle.tar.gz
tar -xvf aac_encoder_plugin-linux-bundle.tar.gz
cd aac_encoder_plugin-linux-bundle

# Install the plugin to DaVinci Resolve
sudo ./install.sh

Step 28 — Affinity Photo/Designer/Publisher (in Distrobox)

Runs Affinity apps via Wine inside an isolated container. Zero footprint on host — delete the container and everything is gone.

# Create a dedicated container
distrobox create --name affinitybox --image fedora:44

# Enter the container
distrobox enter affinitybox

# Inside the container — install dependencies
sudo dnf install python3-pyqt6 python3-pyqt6-svg -y

# Run the Affinity installer GUI
curl -sSL https://raw.githubusercontent.com/ryzendew/AffinityOnLinux/refs/heads/main/AffinityScripts/AffinityLinuxInstaller.py | python3

The GUI installer will guide you through Wine setup and Affinity installation.

When the GUI opens:

  1. Click "One-Click Full Setup" — it configures Wine and all dependencies automatically
  2. When asked for Wine version — pick Wine 10.10 (recommended)
  3. Use "Update Affinity Applications" to install Affinity Photo, Designer, Publisher, or the unified v3 app

[!NOTE]
The Python GUI installer includes OpenCL support, which means your RX 9070 XT will accelerate photo editing filters and effects inside Affinity. The AppImage method does not have this.

After installing, export the app so it appears in your KDE app launcher like a normal app:

# Still inside the container — export the app to host
distrobox-export --app affinity-photo     # or affinity-designer, affinity-publisher

Now you can find and launch Affinity from your normal app menu — no need to manually enter the container each time.

[!TIP]
To completely remove Affinity (zero traces left):
``bash
distrobox stop affinitybox
distrobox rm affinitybox
``

Updating containerized apps

DaVinci Resolve:

The setup.sh script manages your container installation. Run it from inside the ~/davincibox folder using different arguments:

  • Install: ./setup.sh ~/Downloads/DaVinci_Resolve_Studio_21.0_Linux.run — builds the container, verifies your file, extracts it, installs Resolve, and creates a desktop shortcut.
  • Upgrade: First, download the new .run installer from blackmagicdesign.com. Then run ./setup.sh upgrade to remove the old container, followed by ./setup.sh ~/Downloads/DaVinci_Resolve_Studio_NEW_VERSION_Linux.run to do a fresh install with the new version.
  • Remove: ./setup.sh remove — deletes the DaVinci Resolve shortcut from your desktop and completely removes the container.
