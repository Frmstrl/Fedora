Step 2 — Btrfs snapshots (safety net)

If anything goes wrong — reboot, pick a snapshot from GRUB, done.

sudo dnf install snapper libdnf5-plugin-actions btrfs-assistant inotify-tools git make -y

sudo bash -c "cat > /etc/dnf/libdnf5-plugins/actions.d/snapper.actions" <<'EOF'
# Get snapshot description
pre_transaction::::/usr/bin/sh -c echo\ "tmp.cmd=$(ps\ -o\ command\ --no-headers\ -p\ '${pid}')"
# Creates pre snapshot before the transaction and stores the snapshot number in the "tmp.snapper_pre_number" variable.
pre_transaction::::/usr/bin/sh -c echo\ "tmp.snapper_pre_number=$(snapper\ create\ -t\ pre\ -c\ number\ -p\ -d\ '${tmp.cmd}')"
# If the variable "tmp.snapper_pre_number" exists, it creates post snapshot after the transaction and removes the variable "tmp.snapper_pre_number".
post_transaction::::/usr/bin/sh -c [\ -n\ "${tmp.snapper_pre_number}"\ ]\ &&\ snapper\ create\ -t\ post\ --pre-number\ "${tmp.snapper_pre_number}"\ -c\ number\ -d\ "${tmp.cmd}"\ ;\ echo\ tmp.snapper_pre_number\ ;\ echo\ tmp.cmd
EOF

sudo snapper -c root create-config /
sudo restorecon -RFv /.snapshots
sudo snapper -c root set-config ALLOW_USERS=$USER SYNC_ACL=yes

echo 'PRUNENAMES = ".snapshots"' | sudo tee -a /etc/updatedb.conf

git clone https://github.com/Antynea/grub-btrfs
cd grub-btrfs

sed -i.bkp \
-e '/^#GRUB_BTRFS_SNAPSHOT_KERNEL_PARAMETERS=/a \
GRUB_BTRFS_SNAPSHOT_KERNEL_PARAMETERS="rd.live.overlay.overlayfs=1"' \
-e '/^#GRUB_BTRFS_GRUB_DIRNAME=/a \
GRUB_BTRFS_GRUB_DIRNAME="/boot/grub2"' \
-e '/^#GRUB_BTRFS_MKCONFIG=/a \
GRUB_BTRFS_MKCONFIG=/usr/bin/grub2-mkconfig' \
-e '/^#GRUB_BTRFS_SCRIPT_CHECK=/a \
GRUB_BTRFS_SCRIPT_CHECK=grub2-script-check' \
config

sudo make install
sudo systemctl enable --now grub-btrfsd.service
cd ..
rm -rfv grub-btrfs

sudo systemctl enable --now snapper-timeline.timer
sudo systemctl enable --now snapper-cleanup.timer

sudo grub2-editenv - unset menu_auto_hide

From now on, snapshots are created automatically every hour, and before/after every dnf transaction.

How to roll back if your system breaks:

  1. Reboot your PC.
  2. In the GRUB boot menu, select "Fedora Linux snapshots" and boot into a recent working snapshot.
  3. Once you reach the desktop, open the Btrfs Assistant application.
  4. Go to the Snapper tab ➔ Browse/Restore.
  5. Set "Select target" to the root subvolume.
  6. Select the snapshot you want to revert to and click Restore.
  7. Click Yes to confirm, then reboot immediately to permanently apply the rollback. Your personal files (in /home) will be completely unaffected!

Step 9 — OpenRGB

sudo dnf install openrgb i2c-tools -y

# Load AMD I2C modules

echo -e "i2c-dev\ni2c-piix4" | sudo tee /etc/modules-load.d/i2c.conf

# Permission to access hardware
sudo groupadd --system i2c 2>/dev/null

# Fix ACPI conflicts for motherboard/RAM RGB (ASUS/Gigabyte/ASRock)
sudo grubby --update-kernel=ALL --args="acpi_enforce_resources=lax"

[!WARNING] System Freezes (Kernel Panics): Using acpi_enforce_resources=lax allows OpenRGB to control motherboard and RAM lights, but it removes a safety lock on your motherboard's thermal sensors. If the system tries to read a temperature at the exact millisecond you change an RGB light, the collision will cause your PC to completely freeze.

What to do: If your PC locks up (screen freezes, buzzing audio), simply hold down your physical power button for 5 seconds to force a shut off, then turn it back on. No permanent damage is done, and everything will be back to normal.

Step 15 — Virtualization (VirtualBox)

VirtualBox is an easy-to-use virtual machine manager. Because it uses custom kernel modules, we install akmods to automatically rebuild its drivers in the background whenever Fedora updates your system kernel.

# Install VirtualBox and the akmod companion
sudo dnf install VirtualBox akmod-VirtualBox -y

# Build the kernel modules for your currently running kernel
sudo akmods --kernels "$(uname -r)"

# Restart the VirtualBox driver service
sudo systemctl restart vboxdrv

# Add your user to the VirtualBox group
sudo usermod -aG vboxusers $USER

After logging out and back in to apply the group permissions, launch VirtualBox from your KDE app launcher.

[!NOTE] Is akmods safe? Yes! If akmods ever fails to rebuild the VirtualBox driver after a massive Fedora kernel update, your system will still boot perfectly normal. You simply won't be able to open VirtualBox until an update is released. It fails gracefully because your operating system does not rely on VirtualBox to function.

How to fix it if it breaks: 1. The quick fix: Restart your PC and select the older, previous kernel from the GRUB boot menu (Fedora always keeps your last 3 kernels installed for emergencies). VirtualBox will instantly work again! 2. The permanent fix: Wait a few days for RPM Fusion to release an update, run sudo dnf update, and then run sudo akmods --force to rebuild the driver for the new kernel.

Step 16 — Tailscale (Mesh VPN)

Zero-config mesh VPN that connects all your devices into a private network. Works through NAT/firewalls without port forwarding.

# Run the official automated install script
curl -fsSL https://tailscale.com/install.sh | sh

# Authenticate and connect to your network (opens browser)
sudo tailscale up

Firewalld zone setup (keeps Tailscale traffic separate from your main network rules):

sudo firewall-cmd --permanent --new-zone=tailscale
sudo firewall-cmd --permanent --zone=tailscale --add-interface=tailscale0
sudo firewall-cmd --permanent --zone=tailscale --set-target=ACCEPT
# Allow direct peer-to-peer WireGuard tunnels (reduces latency)
sudo firewall-cmd --permanent --add-port=41641/udp
sudo firewall-cmd --reload

[!NOTE] Why do we need this firewall setup? Out of the box, Fedora's firewall is highly restrictive. If you do not configure it, it will block your other Tailscale devices from accessing this PC, and it will force your VPN traffic to route slowly through Tailscale's global relay servers.

What this code does: 1. It creates an isolated, trusted "bucket" (a zone) specifically for your Tailscale interface (tailscale0) so your personal devices can talk to each other. 2. It opens UDP port 41641. This allows Tailscale to form direct, high-speed peer-to-peer connections.

How it affects standard usage: This all happens silently in the background. It does not weaken your computer's main security because the "trust" is only applied to the private VPN network. Your standard internet connection (Wi-Fi or Ethernet) remains fully locked down by Fedora's default strict firewall rules.

Step 17 — Sunshine (Game Streaming)

Streams your desktop and games to any device running the Moonlight client. Pairs perfectly with Tailscale for remote streaming.

# Enable the official LizardByte COPR repository
sudo dnf copr enable lizardbyte/stable -y

# Install Sunshine
sudo dnf install Sunshine -y

Firewall rules (Required for Local Network Streaming): Unlike other operating systems, Fedora's firewall aggressively blocks incoming local network traffic. These are the exact ports required by the NVIDIA GameStream protocol to stream video and receive controller inputs. (Fun fact: Even though you have an AMD graphics card, Sunshine reverse-engineers NVIDIA's ultra-fast streaming protocol so you get the exact same low-latency performance).

sudo firewall-cmd --permanent --add-port={47984,47989,48010}/tcp
sudo firewall-cmd --permanent --add-port={5353,47998,47999,48000,48002,48010}/udp
sudo firewall-cmd --reload

Enable Avahi (mDNS auto-discovery for Moonlight):

sudo dnf install avahi -y
sudo systemctl enable --now avahi-daemon

Start Sunshine as a user service:

# Start Sunshine in the background
systemctl --user enable --now sunshine

# Allow Sunshine to keep running headlessly even when you are logged out
sudo loginctl enable-linger $USER

How to Connect and Play

1. Initial Setup (On your Fedora PC): * Open your web browser and go to https://localhost:47990 * Ignore the browser security warning (it's a local self-signed certificate) and create an admin username and password.

2. Local Network Play (In your house): * Download the Moonlight app on your phone, TV, or laptop. * Because we installed avahi, Moonlight will automatically see your Fedora PC on your Wi-Fi. * Click your PC. Moonlight will give you a PIN. Type that PIN into the "PIN" tab of your Sunshine Web UI to pair them.

3. Remote Play (Outside your house): * Turn on Tailscale on your Fedora PC and your remote device. * Open Moonlight, click the "+" button, and type in your Fedora PC's Tailscale IP address. * It will connect instantly, bypassing your home router!

[!NOTE] Headless streaming (monitor off): Wayland stops rendering when no display is attached. To stream with your real monitor turned off, buy a cheap HDMI dummy plug (~$5) from Amazon to trick your graphics card into staying awake.

Step 19 — PostgreSQL (Podman + DHI)

Runs PostgreSQL in a security-hardened container from Docker Hardened Images (DHI). The cleanest way to run it is in a rootless Podman container using Quadlet (a feature built directly into Fedora's pre-installed Podman engine). This allows the container to be managed exactly like a native systemd service.

[!NOTE] Prerequisites: DHI requires a free Docker Hub login to pull their hardened images.

1. Authenticate with the DHI registry (one-time):

podman login dhi.io

2. Create persistent data directory:

mkdir -p ~/Database-data/postgres

3. Create the Quadlet configuration:

Create the file at ~/.config/containers/systemd/postgres.container:

[Unit]
Description=PostgreSQL Database Container
After=network-online.target

[Container]
Image=dhi.io/postgres:17-debian13
ContainerName=postgres
PublishPort=127.0.0.1:5432:5432
Volume=%h/Database-data/postgres:/var/lib/postgresql/data:Z
Environment=POSTGRES_USER=daniel POSTGRES_PASSWORD=your_password POSTGRES_DB=mydb

[Service]
Restart=no

4. Activate the service:

systemctl --user daemon-reload
systemctl --user start postgres

[!IMPORTANT] No auto-start by design. Because we set Restart=no and omitted an [Install] section, it will NOT start on boot. This saves ~150-200MB of idle RAM when you're gaming or not developing.

On-Demand PostgreSQL:

  • Where are my files? All database files are stored natively in your home folder at ~/Database-data/postgres. Your data persists even if the container is deleted or updated. The :Z SELinux label ensures the container has permission to read/write to this folder.
  • Start when needed: systemctl --user start postgres
  • Stop when done: systemctl --user stop postgres
  • Check status: systemctl --user status postgres
  • View logs: journalctl --user -fu postgres

5. Connect to the database:

# Connect to the running container
podman exec -it postgres psql -U daniel -d mydb

# Inside psql — verify it works:
SELECT version();
\q

From the host, you can also connect with any standard PostgreSQL client on 127.0.0.1:5432 (user daniel, password your_password, database mydb). Authentication is scram-sha-256 by default — no pg_hba.conf editing needed.

[!TIP] GUI clients: Use DBeaver (sudo dnf install dbeaver) or the PostgreSQL extension in VS Code/Cursor for a visual interface. Connection string: postgresql://daniel:your_password@127.0.0.1:5432/mydb

Step 20 — MongoDB (Podman container)

MongoDB Inc. dropped Fedora support in 2019. The cleanest way to run it is in a rootless Podman container using Quadlet (a feature built directly into Fedora's pre-installed Podman engine). This allows the container to be managed exactly like a native systemd service — no extra downloads required.

# Create persistent data directory
mkdir -p ~/Database-data/mongodb

Create the Quadlet file at ~/.config/containers/systemd/mongodb.container:

[Unit]
Description=MongoDB Database Container
After=network-online.target

[Container]
Image=docker.io/library/mongo:latest
ContainerName=mongodb
PublishPort=127.0.0.1:27017:27017
Volume=%h/Database-data/mongodb:/data/db:Z
Environment=MONGO_INITDB_ROOT_USERNAME=admin MONGO_INITDB_ROOT_PASSWORD=SuperSecretPassword

[Service]
Restart=always

# Activate the service
systemctl --user daemon-reload
systemctl --user start mongodb

[!NOTE] Change SuperSecretPassword to something real. The :Z SELinux label is required on Fedora or the container can't access the volume.

Optional: On-Demand MongoDB

Leaving the MongoDB container always running uses ~200-300MB of idle RAM. If you prefer a leaner system when not developing, you can manage it manually:

  • Where are my files? All of your raw database files are stored natively in your home folder at ~/Database-data/mongodb. Because we mapped this volume, your data persists even if the container is deleted or updated.
  • Start when needed: systemctl --user start mongodb
  • Stop when done: systemctl --user stop mongodb
  • Enable auto-start on boot with: systemctl --user enable mongodb
  • Disable auto-start on boot with: systemctl --user disable mongodb
  • Check server status: systemctl --user status mongodb
  • View server logs: journalctl --user -fu mongodb

How to connect to the database:

  • From your terminal (CLI): Run podman exec -it mongodb mongosh -u admin -p (type the SuperSecretPassword when prompted).
  • From GUI tools / App code: Connect via standard connection string mongodb://admin:SuperSecretPassword@127.0.0.1:27017 using an app like MongoDB Compass or VS Code extensions.

Step 21 — Multi-Account Git Setup (Workspaces + SSH)

Quick config to separate personal and work/university repositories by folder — no manual account switching needed.

1. Generate SSH keys:

ssh-keygen -t ed25519 -C "personal@email.com" -f ~/.ssh/id_ed25519_personal
ssh-keygen -t ed25519 -C "work@fhnw.ch" -f ~/.ssh/id_ed25519_work

Add the public keys (.pub) to the respective profiles:

  • ~/.ssh/id_ed25519_personal.pub → GitHub → Settings → SSH and GPG Keys
  • ~/.ssh/id_ed25519_work.pub → GitLab → Preferences → SSH Keys

2. Route keys by host (~/.ssh/config):

Create or edit ~/.ssh/config (ensure permissions with chmod 600 ~/.ssh/config):

Host github.com
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_ed25519_personal
    IdentitiesOnly yes

Host gitlab.fhnw.ch
    HostName gitlab.fhnw.ch
    User git
    IdentityFile ~/.ssh/id_ed25519_work
    IdentitiesOnly yes

3. Create project directories:

mkdir -p ~/Projects/Personal ~/Projects/Work

4. Git config with conditional includes:

~/.gitconfig (main):

[core]
    editor = nano

[user]
    name = Your Name
    email = personal@email.com

[includeIf "gitdir:~/Projects/Personal/"]
    path = ~/.gitconfig-personal

[includeIf "gitdir:~/Projects/Work/"]
    path = ~/.gitconfig-work

~/.gitconfig-personal:

[user]
    email = personal@email.com

~/.gitconfig-work:

[user]
    email = work@fhnw.ch

5. Install platform CLIs:

sudo dnf install gh glab -y
gh auth login
glab auth login --hostname gitlab.fhnw.ch

6. Verify:

# Test SSH authentication
ssh -T git@github.com
ssh -T git@gitlab.fhnw.ch

# Test email override — init a repo inside a target folder and check:
cd ~/Projects/Work && git init test && cd test
git config user.email   # Should show work@fhnw.ch
cd ~ && rm -rf ~/Projects/Work/test

[!TIP] Git's includeIf "gitdir:" matches any repo inside that directory tree. As long as you clone work repos into ~/Projects/Work/ and personal repos into ~/Projects/Personal/, the correct identity is applied automatically.

Step 24 — DaVinci Resolve 21.0 (in Distrobox)

Before starting: download the DaVinci Resolve 21.0 .run installer from blackmagicdesign.com.
Leave the downloaded DaVinci_Resolve_Studio_21.0_Linux.run file in ~/Downloads.

[!NOTE] Important setup details from the davincibox guide: - lshw dependency: lshw is required by the setup script to detect whether you are using an Nvidia, AMD, or Intel GPU. Step 29 — Ollama (AI Model Server for Remote Access)

Turns your Fedora PC into an AI inference server that any device on your Tailscale network can connect to — including Cherry Studio on your Mac.

# Install Ollama
curl -fsSL https://ollama.com/install.sh | sh

Expose Ollama to your Tailscale network:

By default, Ollama only listens on localhost. To allow your other devices (like your Mac) to connect through Tailscale, override the bind address:

sudo systemctl edit ollama.service

Add these lines in the editor:

[Service]
Environment="OLLAMA_HOST=0.0.0.0"

sudo systemctl daemon-reload
sudo systemctl restart ollama

Download a model to test with:

# Download and chat (type /bye to exit)
ollama run llama3.1

[!NOTE] No firewall rules needed! Because your Tailscale zone is set to ACCEPT (Step 16), Ollama's port 11434 is automatically accessible to all your Tailscale devices. Your main network remains fully locked down.

Connect from your Mac (or any Tailscale device):

  1. Make sure Tailscale is running on both your Fedora PC and your Mac.
  2. Get your Fedora PC's Tailscale IP: tailscale ip -4 (outputs a 100.x.x.x address).
  3. Open Cherry Studio on your Mac → Settings → Providers → Ollama.
  4. Set the API URL to http://100.x.x.x:11434 (replace with your actual Tailscale IP).
  5. Click Check — it will connect through the Tailscale tunnel and pull your available models.

You can now chat with local AI models from your Mac, with all the heavy GPU processing happening silently on your Fedora PC.

System Updates & Maintenance

Keeping your system updated is simple, and your Btrfs/Snapper setup ensures you can't break your computer during the process.

System & Flatpak Updates

You can update everything graphically by opening the Discover store and clicking "Update All". Or, use the terminal:

# Update core OS, drivers, and RPM packages
sudo dnf upgrade -y

# Update all sandboxed Flatpak apps
flatpak update -y

How Snapshots Work During Updates:
Thanks to the DNF hook we configured in Step 2, running a dnf upgrade automatically triggers Snapper to take a snapshot before the update and another snapshot after the update. If a bad kernel or GPU driver update causes your system to fail to boot, simply restart, select the pre-update snapshot from your GRUB menu, and your system will be instantly restored.

Updating AppImages (Cherry Studio / LM Studio)

AppImages do not update via DNF or Flatpak. To update an AppImage:

  1. Download the new .AppImage version from the app's website.
  2. Open Gearlever.
  3. Drag and drop the new AppImage into Gearlever. It will ask if you want to replace the existing application. Say yes, and your application shortcuts will automatically point to the new version without breaking.

Updating Containerized Apps

DaVinci Resolve:

The setup.sh script manages your container installation. Run it from inside the ~/davincibox folder using different arguments:

  • Install: ./setup.sh ~/Downloads/DaVinci_Resolve_Studio_21.0_Linux.run — builds the container, verifies your file, extracts it, installs Resolve, and creates a desktop shortcut.
  • Upgrade: First, download the new installer from blackmagicdesign.com and extract the .zip file to get the new .run script. Then run ./setup.sh upgrade to remove the old container, followed by ./setup.sh ~/Downloads/DaVinci_Resolve_Studio_NEW_VERSION_Linux.run to do a fresh install with the new version.
  • Remove: ./setup.sh remove — deletes the DaVinci Resolve shortcut from your desktop and completely removes the container.
